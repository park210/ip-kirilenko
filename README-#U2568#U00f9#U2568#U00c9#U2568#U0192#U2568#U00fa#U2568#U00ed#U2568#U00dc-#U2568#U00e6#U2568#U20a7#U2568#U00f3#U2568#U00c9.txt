КИРИЛЕНКО-СТРОЙ — САЙТ С TELEGRAM-ЗАЯВКАМИ
==========================================

ЧТО ИЗМЕНИЛОСЬ
--------------
1. В корзине добавлена форма: имя, телефон, адрес доставки, комментарий.
2. Кнопка отправляет заявку на сервер сайта.
3. Сервер проверяет товары и цены по собственному каталогу. Цена не берётся
   из присланной браузером суммы.
4. Сервер отправляет заявку в Telegram указанному получателю.
5. Токен Telegram хранится только в переменных окружения сервера.
6. Добавлены базовые HTTP-заголовки безопасности и ограничение частоты запросов.

ВАЖНО ПРО ТОКЕН
---------------
В ZIP нет настоящего BOT_TOKEN. Его нельзя помещать в HTML/JavaScript,
публиковать в GitHub или отправлять в этот чат. Если токен уже раскрывался,
перевыпустите его через BotFather.

КАК ПОЛУЧИТЬ CHAT ID ПОЛУЧАТЕЛЯ
-------------------------------
1. Получатель (например, твой друг) должен открыть именно твоего бота в Telegram
   и нажать Start. Это личное действие получателя.
2. На компьютере в папке проекта создай файл .env по образцу .env.example и
   вставь туда BOT_TOKEN. ADMIN_CHAT_ID пока можно оставить пустым.
3. В терминале выполни npm install, затем npm run get-chat-id.
4. Скрипт покажет чаты, которые писали боту. Выбери личный чат нужного человека.
5. Скопируй его Chat ID. Сам токен никому не отправляй.

ЛОКАЛЬНЫЙ ЗАПУСК
---------------
Требуется Node.js 18 или новее.

1. Распакуй ZIP.
2. Открой терминал в папке, где лежит package.json.
3. Выполни npm install.
4. Скопируй .env.example в файл .env.
5. В .env укажи BOT_TOKEN и ADMIN_CHAT_ID.
6. Выполни npm start.
7. Открой http://localhost:3000.

ПУБЛИКАЦИЯ НА RENDER
--------------------
В корне есть render.yaml для настройки Node Web Service.
1. Загрузить проект в приватный GitHub-репозиторий.
2. В Render создать Blueprint и выбрать этот репозиторий.
3. В Environment добавить BOT_TOKEN и ADMIN_CHAT_ID как секретные значения.
4. После развёртывания проверить адрес сайта + /api/health — должен вернуться
   JSON с "ok": true.

Сервер должен быть Node.js Web Service, а не Static Site: статический хостинг
не сможет выполнить server.js и отправлять заявки в Telegram.

ПРОВЕРКА
--------
1. Получатель заранее нажимает Start у бота.
2. В ADMIN_CHAT_ID указан его личный Chat ID.
3. На сайте добавить тестовый материал, заполнить форму тестовыми данными и
   отправить заявку.
4. Получатель должен увидеть сообщение с контактами, адресом, позициями,
   количеством и предварительной суммой.

ДАННЫЕ КЛИЕНТОВ
---------------
Форма передаёт менеджеру имя, телефон, адрес доставки, список материалов и
необязательный комментарий. Перед публикацией для реальных клиентов владелец
бизнеса должен проверить и добавить подходящее уведомление о конфиденциальности
и необходимые документы/согласия. Тестируйте только на своих данных либо с
разрешения человека, которому принадлежат контактные данные.
